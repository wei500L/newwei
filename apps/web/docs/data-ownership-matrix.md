# Frontend Data Ownership Matrix

This matrix fixes the default ambiguity between Apollo, React Query, client `fetch`, and realtime channels. Each resource should have one primary owner. Realtime channels may invalidate or patch that owner, but should not become a second cache.

## Dashboard

| Page / module                                              | Resource                            | Primary owner                              | Secondary channel                              | Invalidates / refreshes                                                        | Notes                                                                                                                                                                                                                                                                   |
| ---------------------------------------------------------- | ----------------------------------- | ------------------------------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dashboard-content` + `analysis-stream` + `analysis-panel` | `AnalysisResults`, `analysisEvents` | Apollo via `DashboardAnalysisFeedProvider` | GraphQL subscription                           | Manual `refetch()` only                                                        | One query + one subscription shared by both panels.                                                                                                                                                                                                                     |
| `time-range.ts` + `use-dashboard-range-url-sync`           | Dashboard time-window anchor        | Zustand store                              | URL query params, short-lived session snapshot | Preset/custom changes update the owner; URL params still override when present | The initial dashboard window now bootstraps synchronously from explicit URL params or a short-lived session snapshot before charts mount. That keeps same-window reload/new-document hops on one `start/end` anchor instead of regenerating fresh ISO keys immediately. |
| `system-health-context`                                    | `QueueStats`                        | Apollo                                     | Socket `/queue`                                | Debounced `refetchQueueStats()` on queue events                                | `queueStatus` UI filter no longer invalidates `["dashboard"]` or refetches queue stats.                                                                                                                                                                                 |
| `hero-metrics`                                             | Hero metrics                        | React Query                                | None                                           | Query key on time range                                                        | Domain owner stays React Query.                                                                                                                                                                                                                                         |
| `sector-heatmap`                                           | Sector heatmap                      | React Query                                | Dashboard SSE                                  | SSE invalidates exact query key                                                | Retained as explicit hot data path.                                                                                                                                                                                                                                     |
| `financial-candlestick`                                    | Candlestick                         | React Query                                | Dashboard SSE                                  | SSE patches / invalidates exact query key                                      | Retained as explicit hot data path. The query now keeps a 30s stale window so same-window client re-entry does not immediately refetch while SSE is already the freshness path.                                                                                         |
| `war-map`                                                  | War map events / markers / layers   | React Query                                | Dashboard SSE                                  | URL-hydrated first fetch, then SSE-coalesced prefix invalidation               | War-map monitors now share the same monitors owner as `situation-monitor`. Initial URL state is applied before enabling queries so first paint does not burn a default-range request, and SSE only refetches active prefixes after a short cooldown.                    |
| `use-dashboard-stream`                                     | Stream transport                    | Native `fetch(..., { cache: "no-store" })` | SSE                                            | Invalidates or patches React Query owners                                      | Secondary channel only, not a cache owner.                                                                                                                                                                                                                              |

## Crawl

| Page / module                    | Resource                    | Primary owner                                                   | Secondary channel             | Invalidates / refreshes                                                                                                         | Notes                                                                                                                                                                         |
| -------------------------------- | --------------------------- | --------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `crawl-tasks.tsx`                | Crawl task list             | Local component state fed by Apollo `useCrawlTasksLazyQuery`    | Socket `/ops`                 | Silent `reloadTasks()` on crawl `ACTIVE`/`COMPLETED`/`FAILED` events and reconnects                                             | Apollo fetch policy is `no-cache` to avoid a redundant second cache. | `news-sources-content.tsx`       | News source ops list        | Local component state + REST `GET /admin/news-sources`          | Socket `/ops`                 | Silent current-page `refreshAll()` on matching `pipeline` / `crawl` source events, reconnects, or disconnected fallback polling | REST owns pagination/search/read model. `/ops` only invalidates the current page when `sourceId` is visible; fallback polling is enabled only while realtime is disconnected. |
| `crawl-tasks.tsx`                | Crawl client settings       | Form state fed by Apollo `useCrawlClientSettingsQuery`          | None                          | Explicit `refetchCrawlClientSettings()`                                                                                         | Apollo fetch policy is now `no-cache`.                                                                                                                                        |
| `crawl-tasks.tsx`                | Metadata extraction preview | Local component state fed by Apollo `useCrawlMetadataLazyQuery` | None                          | On-demand fetch                                                                                                                 | Apollo fetch policy is now `no-cache`.                                                                                                                                        |
| `crawl-tasks.tsx`                | Queue ops stats             | Local component state + REST                                    | Socket `/ops`                 | Silent `loadQueueStats()`                                                                                                       | REST remains the only owner.                                                                                                                                                  |
| `crawl/[taskId]/task-detail.tsx` | Crawl task detail           | Apollo                                                          | Socket `/ops`, Apollo polling | `refetch()` on matching crawl/pipeline terminal events or reconnect; 3s polling only while disconnected and in-flight           | Apollo now uses `cache-and-network` with `nextFetchPolicy: "cache-first"` so the detail view stays hot without forcing every watch to bypass cache.                           |
| `crawl/[taskId]/task-detail.tsx` | Task logs                   | Local component state + REST                                    | None                          | Initial load + manual refresh only                                                                                              | REST remains the only owner; logs no longer auto-refresh from socket or fallback timers.                                                                                      |
| `Crawl4aiHealthCard`             | Health/runtime              | Local component state + `no-store` fetch                        | Interval polling              | Internal `load()`                                                                                                               | Operational monitoring path retained.                                                                                                                                         |

## Retained Exceptions

- `cache-and-network`, `network-only`, polling, and `no-store` should remain only on explicitly hot paths:
  - Dashboard SSE-backed charts.
  - Crawl task detail while the task is in flight.
  - Crawl health/runtime operational probes.
  - Situation-monitor HLS probe checks.
- `apps/web/lib/server-graphql.ts` still defaults to `cache: "no-store"`, but the four domains above do not currently depend on it. It was left unchanged in this pass to avoid broad unrelated behavior changes.
