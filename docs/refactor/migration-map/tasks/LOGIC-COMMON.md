# LOGIC 系列通用执行纪律（业务逻辑修复）

LOGIC-* 任务修复的是 [业务逻辑复审报告](../LOGIC-REVIEW-01-PROCESSING.md) 中已核实的缺陷。**开工、worktree、验证、提交与交付这几部分的规则，与 [REFACTOR-COMMON](REFACTOR-COMMON.md) 完全相同**，先完整读它。下面只列出与它不同、或需要加强的地方。

## 与 REFACTOR 的根本区别：这是有意的行为变更

- REFACTOR 要求“行为不变”；LOGIC 任务的目的恰恰是**改变错误的行为**。
- 能改的只有任务明确列出的行为。任务以外的对外契约保持不变，包括：
  - HTTP/GraphQL 字段名与状态码；
  - Redis key 与存储格式；
  - BullMQ 的 wire 格式。
- 每一处行为变更，PR 中都要写清：
  - 修复前的行为（附 `file:line`）；
  - 修复后的行为；
  - 会影响哪些已有数据或页面；
  - 是否需要处理历史数据。
- **不再以“与 NestJS 等价”为理由保留缺陷**。顺手发现的注释，例如“exactly like the TypeScript …”“mirrors NestJS …”，如果它描述的正是本次修掉的行为，就改成当前事实。

## 测试要求（比 REFACTOR 更严格）

- 每个修复都要有**先失败、后通过**的单元测试，即复现缺陷场景的回归测试。测试名直接写清场景，例如 `TestOverlapDoesNotMergeWhenVectorSaysDissimilar`。
- 原有测试中断言了**缺陷行为**的，要改断言，并在 PR 中逐条列出“改了哪条断言、为什么”。其余原有断言不得修改。
- 算法类修复（分类打分、事件归并）在测试中构造一组**有代表性的样例**：同主题不同事件、跨语言、中文、低置信度、所有层都失败等。PR 中附一张修复前后结果的对照表。

## 本机验证禁令（重申）

- 本机**禁止**运行 `go build`、`go test`、`go vet`、`pnpm test`、Docker 或任何服务。上一轮有执行窗口违反了这一条，这次严格执行。
- 允许运行的只有 `gofmt -l` / `gofmt -w`（只针对自己改过的文件）和 grep/find。
- 唯一的运行证据，是普通 CI 在**精确 head SHA** 上的结果。

## 配置项

- 任务要求新增设置项时，同时修改三处：
  - 后端读取设置的地方：默认值、取值范围，并在读取时 clamp；
  - GraphQL 设置模型；
  - `apps/web` 中对应的设置界面与 `zh`/`en` 文案。
  
  这是 AGENTS.md 中“端到端交付”的要求。
- 默认值取任务给出的值。不要为了“兼容旧行为”默认关闭修复。
